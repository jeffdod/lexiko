# lexiko

Build your Greek vocabulary. Read the Greek New Testament with confidence. A free, offline-first Progressive Web App: no login, no server, hosted as static files on GitHub Pages.

**What it has:** a tap-for-parsing reader, vocabulary spaced repetition (FSRS), parsing and principal-parts practice, passage readiness and goals, reference charts with chart practice, a glossary, backup/restore, and an offline PWA shell.

## Use it
Open `https://lexiko.org/` and "Add to Home Screen" / "Install app". It then runs full-screen and fully offline.

## Deploy (GitHub Pages)
1. Push this folder's contents to the repo root (`main`).
2. Repo → Settings → Pages → *Deploy from a branch* → `main` / `(root)`. (Free Pages requires a public repo.)
3. `.nojekyll` is included. All paths are relative, so it works under `/lexiko/` or a custom domain.

## Rebuild after changes (needs Python 3 + fontTools, Node)
```
python3 tools/build_data.py sources/rp sources/lexicon/Dodson-Ulrik.txt sources/lexicon/user-lexicon.txt data   # RP + lexicon -> data/*.json
python3 tools/build_pericopes.py sources/pericopes/kretzmann.txt data                                  # section headings -> data/pericopes.json
python3 tools/make_fonts.py <GentiumPorsonic dir> fonts                                               # subset + rename + woff2
python3 tools/make_icons.py && node tools/render_icons.js                                              # icons, favicon, social card
python3 tools/build_sw.py        # ALWAYS run after changing any app file: regenerates the offline precache list/version
node tools/serve.js &            # local test server at http://localhost:8123/lexiko/ (or double-click preview.command / preview.bat)
node tools/test_smoke.js         # end-to-end test in headless Chromium (needs playwright)
node tools/test_round2.js        # home, keyboard, charts, undo, search-related checks, phone-width reader
node tools/test_parts.js         # principal-parts practice
node tools/test_a11y.js          # names, tap targets and contrast, light and dark
```

### Prepositions that take several cases
`sources/lexicon/Dodson-Ulrik.txt` is the single source of both the short (brief) and long definitions. Tag the parts of a preposition's definition in either column with `gen:`, `dat:` or `acc:` (for example `(a) gen: through, (b) acc: on account of`). When the short gloss has two or more different cases, the preposition is learned as one word per case ("διά + genitive", "διά + accusative"), each with its own review schedule, short gloss and long definition. The reader popup shows the sense for the case the preposition governs in that verse (it looks at the next case-bearing word, and shows every sense when that is unclear). A preposition with only one case, or none, stays a single word: the question screen shows just the word (no "+ case"), and its definition is shown exactly as written in your file, tag included. Quizzes test the short gloss; the long definition appears after answering only when it adds something, and sits behind "More" when it is long. Rebuild the data (command above), then `python3 tools/build_sw.py`.

Users get new versions automatically: the service worker notices a changed `sw-assets.js`, downloads the update, and shows an "Update ready — Reload" banner.

## How it works
* `data/` – `lexicon.json` (5,381 lexemes: Strong's no., headword, gloss, frequency), `forms.json` (20,591 distinct word forms with soft hyphens and RP parsing; alternate parsings kept), `text/XXX.json` (one token stream per book, ints = form id × 16 + punctuation (0–4) + 8 if an em-dash follows the word; in the Beta source a trailing `-` or `_` marks that dash, and the following space is dropped). `pericopes.json` holds 589 section headings; each runs to the verse before the next heading.
* Words are keyed by **Strong's number**; frequencies are counted from the RP text itself.
* A word is *known* if you have a mature SRS card for it, or (no card yet) its frequency ≥ your declared level. Missing a "known" word in a check-in demotes it to learning.
* Passage readiness = share of the running words you know. ≥98 % Ready · 95–98 % Comfortable · 90–95 % Stretch · 80–90 % Challenging.
* Progress is stored in IndexedDB; the app requests persistent storage and offers JSON backup/restore (merge or replace).

## Principal parts
`#/parts` drills the six principal parts of ~1,300 verbs (`data/parts.json`, built by `python3 tools/build_parts.py <spreadsheet.xlsx>`; each part printed for a verb is one FSRS card `p:<strongs>:<slot>`). Several spreadsheet rows can share one Strong's number, so a row is chosen by matching the lexicon headword (else by how often its forms occur). Two question types: *recognise* (see a part → pick the verb → pick which part) and *recall* (verb + part name → pick the form from plausible look-alikes, or remember it and rate yourself). *Auto* starts with multiple choice and moves to self-graded flashcards at ≥85 % over 20 answers (back below 60 % over 12). Pools: verbs you're learning, or the verbs of a passage. `js/parts.js`; tests: `node tools/test_parts.js`.

## Learn pages
`#/learn` has one **Start** button and three topics (Vocabulary `#/learn/words`, Parsing `#/parse`, Principal parts `#/parts`). `js/smart.js` decides what Start does: reviews that are due, then new material, then **Reinforce** (your shakiest cards), then a preview — so it never says there is nothing to do. Each topic page has the same single button, a *Preview new* link, and collapsed *Study a passage* and *Options* sections.

## Strengthen weak spots, look ahead and charts
Vocabulary, parsing and principal parts each have *Strengthen weak spots* (your shakiest cards) and *Look ahead* (a few cards you haven't started). Neither ever writes a card, counter or statistic, so the spaced schedule is untouched. Every quiz screen has a **Charts** button (`js/charts.js`) with four tabs: the master verb chart, personal endings, noun endings (the first/second and third declension charts from the user's grammar) and contractions. After a verb or noun answer, the matching row is highlighted, and the parsing feedback has a button that opens it.

## Parsing practice
Parsing a passage (Study a passage) has two one-click buttons for the same text: all forms, or **Verbs only**.
`#/parse` quizzes the parts of a form in a fixed order (verbs: tense → voice → mood → person → number; infinitives stop after mood; participles continue with case → number → gender; other words: case → number → gender). Every parsing listed for the form under the same lexeme is accepted, each part is scored separately, and every form has its own FSRS card (`f:<form>:<strongs>`). *Guided* asks one part at a time with instant feedback and a hint; *Quick* shows all parts at once; *Auto* starts guided and switches (per verbs / other words) once you're ≥85 % reliable over 20 forms, and back below 60 %. Code: `js/parse-model.js` (slots, matching, grading), `js/parse.js` (UI). `node tools/test_stem.mjs [form…]` checks them against the whole text.

**Practice by form** (on the Parsing page; practice only, nothing changes the review schedule): *Parse from the chart* (`js/chartpick.js`, `#/learn/charts/pick`) picks rows of the master verb chart and quizzes real forms of those rows (at least 8, at least one per row); *Clue hunt* (`js/cluehunt.js`, `#/parse/run/clues/known|any`) asks for the clues in order (augment or reduplication, tense stem, tense formative, endings) before naming the form, with a contrast pair of two easily confused forms of one verb every third question. Pairs are drawn at random but weighted by how weak you are, in Parsing, in the slots they test (tense, voice); when you are clearly weak in one (under 85 % over at least 10 answers) the pair says why it was chosen. Forms you have missed in Parsing (lapses, or a hard card) are asked more often and say so; the rows come in a random order each time. Clue hunt is gated like the daily quiz (open levels, and known chart rows when “Parse by chart row” is on). *Build the form* (`js/buildform.js`, `#/parse/run/build/known|any`) does it the other way round: you are told the form (tense, voice, person, number, of a verb) and build it one slot at a time (front, stem, tense formative, connecting vowel on thematic rows, personal ending) from real forms in the text. The formative, vowel and ending tiles are the master chart's own pieces (`chartPieces`: κα, σα, θη…); where they run together in the spelling (ο + νσι(ν) is written ουσι(ν); σα is written σε in the 3rd singular) the feedback says so. A form is only offered when front + stem + formative + ending is exactly the word (ignoring accents) and the stem is the verb's own present stem (second aorists and second perfects have their own); -μι, compound, liquid and other irregular verbs are left out. The subjunctive, imperative and infinitive (not perfects, liquid or ψ/ξ-merged forms; contract verbs are included: the present gets a Contraction step with the mood's own rules, e.g. the subjunctive's ε + ῃ → ῃ and the infinitive's α + ει → α (ἀγαπᾶν), and other tenses lengthen the stem vowel as in the indicative) are built too, from the same splits the mood pages use (`js/subdata.js`, `js/impdata.js`, `js/infdata.js`; `decomposeMood`, `moodPool` in `js/parse.js`): there is no augment, so no Front step: stem, tense formative (σ, θ, σα, θη, η or none), connecting vowel (the long ω/η, or the imperative's ε) and personal ending; an infinitive is stem and ending. They wait for their level like the other forms, and the paradigm is shown at the end instead of the master chart row. Participles of all ten kinds (`decomposePtc`, `ptcPool` in `js/parse.js`, split with `split()` from `js/ptcdata.js`) are built too: front (perfects only: reduplication, or the vowel's lengthening), stem, tense formative (ο/ου/ω, σα, θε, ε, κ or none) and ending (the participle marker -ντ-, -μενο- or -οτ- together with the case ending); the tested paradigm row for that case and number is shown at the end. A participle is only offered when the pieces add up exactly to the word and the stem is the verb's own (second aorists are checked against the printed principal part; -μι and compound verbs and perfects with changed stems are left out). Present participles of contract verbs get a Contraction step like the other moods (ε + ο → ου: ποιοῦντες), and their other tenses lengthen the stem vowel. Liquid verbs (stem in λ, μ, ν, ρ) are built in the liquid aorist active (`aor-liq-act`), the liquid futures (`fut-liq-act`, `fut-liq-mid`) and in the 1st aorist subjunctive, imperative, infinitive and participle: there is no σ, and the stem is the one printed in the verb's principal parts (μένω: ἔμεινα → μειν-, μενῶ → μεν-; ἐγείρω: ἐγερῶ → ἐγερ-), with a note; verbs that keep a σ (φθάνω, ἁμαρτάνω) and ἦρα-type lengthenings are left out. **The word is built in place**: the strip shows the word so far, not separate boxes. Steps run in word order from the stem (Stem, Front, Prefix, Tense formative, Connecting vowel, Personal ending, then a Sound change step where the pieces side by side are not yet the word, and Contraction), each new piece goes where it belongs in the word (a lengthened vowel replaces the stem's own first vowel; a prefix goes in front) and is highlighted, `indicSteps`/`moodSteps` hold the steps and the word after each. **Compound verbs** (about 680 lexicon verbs, found in `js/compound.js`: the rest after the preposition must be a verb of its own, so ἐγείρω, καθαρίζω and ἐγγίζω are never split) get a Prefix step first (ἀποστέλλω: ἀπ-, because the final vowel drops before the augment), then the simple verb is built as usual in every mood and in the participles; the augment or reduplication goes after the prefix. **Perfect middle/passive** forms of stop and ζ stems (γέγραπται, πέπεισμαι, γεγραμμένος) are built with the stem spelled as the ending requires (`perfJoin`: π, β, φ + μ → μμ, κ, γ, χ + μ → γμ, a dental + μ → σμ, and so on). Liquid verbs with a middle aorist (ἀπεκρίνατο) work too. **-μι verbs** (δίδωμι, τίθημι, ἵστημι and their compounds) are built in the future, the κ-aorist (ἔδωκα, ἔθηκα), the perfect and the aorist and future passive from the stem and formative printed in the principal parts (`miStem`); their present, imperfect, second aorists and the other moods are left out. Stems that end in a stop or ζ are built with the present stem and the sound change named at the end (`soundJoin`): φ/π/β + σ is written ψ, κ/γ/χ + σ is written ξ, a dental (ζ, δ, τ, θ) drops before σ and κ and becomes σ before θ, and a labial or velar is aspirated before θ (πέμπω: ἐπέμφθη); the word is always checked against that spelling, so -σσω/-ττω verbs and verbs with other stems stay out. Vowel-initial verbs are built too in the imperfect, aorist and perfect (not second perfects, and not verbs whose first vowel is already long; a vowel-initial second aorist such as ἦλθον is offered only when the verb's printed principal part gives the same stem, ἐλθ-): the Front step offers *first vowel lengthens*, the stem is shown without the augment (ἀγαπη-), and a *Front (lengthening)* step (in place of Front) asks what the stem's first vowel becomes (α → η, ε → η, ο → ω, αι → ῃ, οι → ῳ, αυ → ηυ), with the rule shown after the answer. Contract verbs (-άω, -έω, -όω) that begin with a consonant are built too: in the present and imperfect the stem keeps its vowel (ποιε-) and a *Contraction* step asks how it is written with the ending (the rule is shown after the answer); in the other tenses the stem vowel lengthens (ποιε- → ποιη-) or stays, shown after the Stem answer; verbs with other stems (καλέω → κλη-) are left out. The `BUILD` table in that file holds the six realized endings for each chart row and is checked against λύω's paradigm in `tools/test_buildform.js`. In the reader, a verb's popup has *Find the clues* for indicative forms: it opens Clue hunt on that exact form with its verse shown and returns to the reading (`js/clueref.js` carries the verse and the way back). For compound verbs the feedback splits the form after the preposition (`splitCompound`: προσ · ε · κύνει). Tests: `node tools/test_chartpick.js`, `node tools/test_cluehunt.js`, `node tools/test_cluereader.js`.

## First run and the Glossary
A brand-new user (no level chosen, nothing studied) sees two plain questions first (`js/welcome.js`): how much Greek they know (which sets the level) and what they want to do first. The **Glossary** (`#/search`, `js/search.js`, under Reference) lists every word, α→ω or ω→α with a letter strip, or most common first, and filters as you type: it finds a word by Greek form with or without accents, by Beta Code, by English meaning, or by Strong's number, and shows its meaning, where it occurs and its forms; all Greek shown comes from the text and lexicon data.

## App layout, shortcuts, word groups, learning curve, locked backups
* **Layout**: the bottom bar is Home, Read, Progress, Settings. **Home** is a goal card (a tap opens Progress; "Change ›" opens the goal picker) and three large buttons: **Vocabulary** (`#/learn/words`: learn, review, look ahead, the pace control), **Verb practice** (`#/parse`: parsing, build a form, chart drills, principal-parts quiz, your verbs; exercises only) and **Reference** (`#/reference`: Glossary, quick charts, verb charts, kinds of form, principal-parts list; study only, no scoring). Study pages link to their exercise with "Practice this ›". `#/learn` redirects to Home.
* **Keyboard** (computers): in vocabulary sessions Space shows the answer, 1–4 rate it (or choose an option), Space continues; parsing and principal-parts quizzes already take Enter and 1–4.
* **Study by how common** (Vocabulary): `#/learn/set/<min>/<max>` teaches the words you don't know yet that occur between min and max times.
* **Learning curve** (`js/growth.js`, Progress): cumulative words started, rebuilt from the per-day counts lexiko already keeps (so it has history from day one).
* **Locked backups**: in Settings an optional passphrase encrypts the backup file (AES-GCM, key from PBKDF2-SHA256, 250,000 rounds; `js/store.js`). The passphrase is never stored; restoring asks for it. Needs a secure context (https or localhost).

## Settings, help, progress and accessibility
* **Settings** keeps the everyday choices up front (look, level, quiz style, new words per day, backup). Spot-check rate and memory target sit under *Advanced*; the passphrase, where backups go and storage status are folded under *Your data*.
* **How lexiko works** (`#/help`, `js/help.js`) is a short, plain-language page linked from Home and Settings.
* **Progress** opens with one calm sentence: how much of the goal passage is known (or, with no goal, how many words you know and how much of the New Testament text they cover, and how far to the next round number).
* **Undo**: a vocabulary session shows “Undo last answer” (or the U key) after each answer; it restores the card, the review log and today's counts (`undoRate` in `js/know.js`). One step only; parsing and principal-parts answers are graded automatically, so they have no undo.
* **Updates**: the app re-checks for a new version whenever it returns to the front and once an hour, and offers “Update ready”.
* **Accessibility checks:** `node tools/test_a11y.js` checks, in light and dark at phone size, that every control has a name, tap targets are at least 40px and text contrast is at least 4.5:1 (3:1 for large text).

## Words and prepositions
* **Preposition cases:** a preposition that governs a name or number with no case ending (for example a proper name) looks at the word after it. The few uses the words around them can't settle are decided by hand in `js/prep-cases.js`: a case, or `-` for a preposition that is really an adverbial prefix and governs nothing (it then shows its plain entry).
* The Dodson-Ulrik file supplies every gloss; `sources/lexicon/user-lexicon.txt` still supplies the headwords.
